# QMT-TOOLKIT

> 面向 QMT 量化交易终端的 Python 小工具与技术实验项目。
>
> 目前以 **QMT 通信与运行环境兼容性测试** 为起点，后续逐步整理调试、数据处理、策略辅助和接口验证等实用工具。

**项目状态：持续整理中 · 测试环境：国金 QMT 模拟交易端**

## 项目简介

**QMT-TOOLKIT** 用于收集和维护 QMT 开发过程中编写的最小化测试脚本、辅助工具和技术实验示例，帮助开发者理解 QMT 内嵌 Python 的能力、依赖关系与运行边界。

本项目不提供交易信号、收益承诺或实盘自动交易方案。所有实验应在**获得授权的隔离模拟环境**中进行，并遵守软件及券商的相关规定。

## 使用说明

1. **准备环境：** 使用获授权的 QMT **模拟交易端**；确认当前没有实盘策略运行。
2. **检查依赖：** 测试脚本涉及外部 Conda Python 3.6 的 `DLLs`、`Lib`、`site-packages` 以及 SQLite 原生 DLL。运行前检查本机目录与脚本配置是否匹配，勿直接沿用示例中的个人电脑路径。
3. **检查源码编码：** 源码头部的 `# encoding: gbk` 应与文件实际保存编码一致。若将源码保存为 UTF-8，需要同步修改编码声明，并检查终端的兼容性。
4. **执行测试：** 在 QMT 模拟策略环境中加载 `test/qmt_ipc_test.py` 的脚本内容，并根据所用终端的策略运行方式执行；当前脚本以 `main()` 为测试入口。
5. **阅读日志：** 在 QMT 的策略日志中查看每个测试项目的输出。

日志标记：`[PASS]` 为当前断言通过；`[FAIL]` 为测试中出现异常；`[SKIP]` 为未满足测试前提；`[WARN]` 为非致命警告。

### 运行前特别提醒

- **DLL 加载影响整个进程。** 外部 Conda 原生库并非全部与 QMT 兼容，尤其注意同名 DLL 冲突及潜在的稳定性影响。
- **测试可能产生系统资源或文件。** 例如 WinAPI 文件读写测试会在用户目录创建测试文件；在已记录的运行中，Python `os.remove()` 清理失败，需要人工检查遗留文件。
- **会调用系统接口。** 部分测试会启动测试子进程，创建临时事件、管道、邮件槽或注册表项；请在可恢复的隔离环境中运行，并核对源码后再执行。

## 结果解读与实验边界

本项目的通信测试主要用于了解**接口的最小可用性**，不代表对应技术已经在实盘、长期运行或两个完全独立的进程之间验证成功。

- **具名管道、具名事件、信号量、Mailslot、具名共享内存：** 主要为同一进程内的多个句柄或映射对象测试，不能直接等同于跨进程测试。
- **Socket：** 验证本地 `127.0.0.1` TCP 收发，不意味着外网访问可用。
- **信号：** 验证处理器注册，并未测试向 QMT 发送外部信号。
- **环境变量：** 仅测试当前进程内读写，不代表独立进程实时共享环境变量。
- **SQLite：** 测试使用 `:memory:`，不能证明磁盘数据库持久化写入可用。
- **Python 文件 I/O：** `tempfile.TemporaryDirectory()` 创建失败，不等于所有 Python 文件操作都不可用；`_winapi` 文件读写成功，也不代表清理操作成功。

不同 QMT 版本、券商发行版、Windows 环境、Python 版本及依赖加载状态，都可能产生不同的结果。
